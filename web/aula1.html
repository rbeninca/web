Conceito · Fundamentos

Internet vs Web

São camadas distintas. Internet é a infraestrutura de rede; Web é um serviço de aplicação que opera sobre ela.

🌐
Internet
Camada de rede
Infraestrutura física: cabos de fibra ótica, roteadores, switches e endereços IP. Tecnologias: TCP/IP, Ethernet, Wi-Fi.
🌍
Web
Camada de aplicação
Serviço que opera sobre a internet usando o protocolo HTTP. Sites, APIs e aplicações web são recursos da Web.
📡
Outros Protocolos
Mesma rede, protocolos distintos
E-mail (SMTP/IMAP), mensagens (XMPP), transferência de arquivos (FTP) — operam na mesma infraestrutura, mas não usam HTTP.
Referência: submarinecablemap.com — mapa interativo dos cabos submarinos de fibra ótica que formam a espinha dorsal da internet.
Arquitetura · Cliente-Servidor

Cliente e Servidor

Toda comunicação na Web segue esse padrão simples: alguém pede e alguém responde.

...

Pressione "Próximo Passo" para iniciar a comunicação.
💻

Cliente (Navegador)

Chrome, Firefox, Safari. Faz requisições (requests) quando você digita uma URL ou clica em um link. Interpreta e renderiza a resposta.

🖥️

Servidor (Web Server)

Apache, Nginx, Node.js. Fica escutando requisições, processa e envia de volta a resposta (response) — geralmente um arquivo HTML.

HTTP · Estrutura da Mensagem

Headers e Body

Toda mensagem HTTP é composta por cabeçalhos (metadados da requisição) e um corpo (dados transmitidos, quando existentes).

Headers — Cabeçalhos
Method:POST
URL:/login
Host:site.com
Content-Type:application/json
Cookie:sessid=abc123
Body — Corpo da Requisição
{
"email": "aluno@ifsc.edu.br",
"senha": "minha_senha_123"
}
No GET o body é vazio — apenas cabeçalhos.
No POST o body carrega os dados da operação.

GET — Recuperar recurso

Body ausente. Solicita um recurso identificado pela URL. Ex: carregar uma página, buscar dados de uma API.

POST — Submeter dados

Body com payload. Envia dados ao servidor para processamento. Ex: autenticação, envio de formulário, upload de arquivo.

DNS · Resolução de Nomes

DNS — Resolução de Nomes de Domínio

Redes TCP/IP usam endereços IP para identificar hosts. O DNS (Domain Name System) mapeia nomes de domínio legíveis para endereços IP numéricos.

  • 1
    Cliente solicita ifsc.edu.brNome de domínio configurado na requisição do navegador.
  • 2
    Consulta ao servidor DNSO resolver local consulta os servidores DNS e obtém o registro A com o endereço IP.
  • 3
    Navegador usa o IP retornadoEstabelece a conexão TCP com o servidor no endereço resolvido.
Registro A: associa um nome de domínio a um endereço IPv4. O registro AAAA faz o mesmo para IPv6.

HTTP · Status Codes

Códigos de Status HTTP

Toda resposta HTTP inclui um código de status — um número de três dígitos que indica o resultado da operação no servidor.

200
OK
Requisição processada com sucesso. O recurso solicitado foi retornado.
301
Moved Permanently
O recurso foi movido definitivamente para outra URL.
401
Unauthorized
Autenticação necessária. O cliente não enviou credenciais válidas.
404
Not Found
O recurso solicitado não existe no servidor.
500
Internal Server Error
Erro interno no servidor. O processamento da requisição falhou.
Regra geral: 2xx Sucesso · 3xx Redirecionamento · 4xx Erro do cliente · 5xx Erro do servidor
HTML · Fundamentos

HTML — A Linguagem de Marcação

Imagine um editor de jornal antigo. Você entrega um texto puro e ele circula partes com marcações na margem: "isso é título", "isso é parágrafo". As tags HTML são exatamente essas marcações.

HTML não cria o conteúdo. Ele diz o que o conteúdo é. O navegador usa essa informação para saber como exibir cada elemento.
HTML ≠ Programação. Não tem lógica, loops ou condições. É apenas estrutura e significado semântico.
Texto puro → Texto marcado
antes.txt → depois.html
texto puro — sem marcação
IFSC – Campus Gaspar
Bem-vindo ao curso!
mesmo texto — com HTML
<h1>IFSC – Campus Gaspar</h1>
<p>Bem-vindo ao curso!</p>
Exercício "O HTML Humano": Pegue um papel com texto puro. Circule o título em vermelho e escreva <h1>. Circule os parágrafos e escreva <p>.

HTML · Estrutura Base

O Esqueleto de toda página HTML

index.html
<!DOCTYPE html>
<html lang="pt-BR">
<head>
<meta charset="UTF-8">
<title>Minha Página</title>
</head>
<body>
<h1>Olá Mundo!</h1>
<p>Meu primeiro parágrafo.</p>
</body>
</html>
  • DTD
    <!DOCTYPE html>Declara ao navegador que é HTML5. Sempre na primeira linha, sem exceção.
  • ①
    <html lang="pt-BR">Raiz do documento. Tudo fica dentro dele. O atributo lang define o idioma da página.
  • ②
    <head>Informações para o navegador: título, ícone, CSS, charset. Não aparece visualmente.
  • ③
    <body>O conteúdo visível. Tudo que o usuário vê e interage fica aqui.
Regra de ouro: Toda tag que abre deve ser fechada (exceto tags auto-fecháveis como <br> e <img>).
DOM · Document Object Model

O DOM — Como o navegador lê o HTML

Quando o navegador recebe o HTML, ele o transforma em uma árvore de objetos — o DOM. É como um organograma da sua página. Cada tag vira um nó da árvore.

document
└─ <html>
├─ <head>
│  └─ <title> "Minha Página"
└─ <body>
├─ <h1 id="titulo">
├─ <p class="intro">
└─ <ul>
├─ <li> "Item 1"
└─ <li> "Item 2"
Por que o DOM importa?
JavaScript usa o DOM para modificar a página sem recarregar. document.getElementById('titulo') pega aquele nó e você pode mudar seu texto, estilo ou posição.

Síntese · As Três Linguagens da Web

O Trio Fundamental

Cada uma tem uma responsabilidade bem definida. Juntas, constroem toda experiência web que você conhece.

🦴
HTML
Estrutura · O Esqueleto
Define o que cada elemento é: título, parágrafo, lista, link, formulário, imagem...
👗
CSS
Aparência · A Roupa
Define como cada elemento parece: cor, tamanho, fonte, espaçamento, layout, animação...
💪
JavaScript
Comportamento · Os Músculos
Define o que cada elemento faz: cliques, formulários, requisições, manipulação do DOM...
HTTP é o sistema circulatório (transporta informação) · Servidor é o cérebro/memória (onde a informação reside) · Navegador é o músculo que executa tudo

Exercício · Trabalho em Dupla

O Algoritmo do Desenho

Sem olhar para a tela do colega, você consegue "codar" uma página apenas ouvindo instruções?

📋 Aluno A — O Narrador

Recebe uma imagem impressa de uma página simples (título, imagem central e dois parágrafos).

  • ❌ Errado: "Coloca um título grande"
  • ✅ Certo: "Abre a tag h1, escreve 'Título', fecha a tag h1"

💻 Aluno B — O Navegador

Está com o editor de código aberto, mas não pode ver a imagem do colega.

  • Só pode codificar o que for narrado
  • Segue as instruções à risca — sem interpretar
  • No final: abre no navegador e compara
Objetivo: Entender que HTML é uma linguagem precisa. Palavras ambíguas geram resultados errados. O navegador não "adivinha" a intenção — ele obedece ao código.
